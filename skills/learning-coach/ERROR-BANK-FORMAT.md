# ERROR-BANK.md 格式

一個概念一則。犯錯時新增，複習後更新狀態。

```markdown
## <概念名稱>

- **狀態**：🔴 完全不理解 ／ 🟠 部分理解 ／ 🟡 容易混淆 ／ 🟢 已經掌握
- **首次犯錯**：YYYY-MM-DD ｜ **最近複習**：YYYY-MM-DD ｜ **不同案例連續答對**：n 次
- **錯誤推理**：<使用者當時的推理鏈，原話引用，不要改寫>
- **斷點**：<推理鏈斷在哪一步。格式：「從 X 推到 Y 時跳過了 Z」>
- **正確邏輯**：<完整推理鏈，一步一句，1→2→3，不跳步>
- **為什麼容易再犯**：<認知成因。例如「跟 A 概念表面相似但前提相反」>
- **例子**：<成立的案例>
- **反例**：<看似成立但不成立的案例——這是分辨真懂假懂的關鍵>
```

## 規則

- **斷點寫的是一個步驟，不是一個知識點。**「不知道 X」是知識缺口，「從 X 推到 Y 時跳過 Z」才是斷點。寫不出步驟就代表還沒診斷完。
- **錯誤推理逐字引用。** 改寫過的答案看不出當時真正的思路。
- **不刪除任何一則。** 掌握了就改狀態成 🟢 並記日期——它是重複犯錯模式的證據來源。
- **狀態升級需要不同案例。** 同一個案例再答對一次不算數。

## 狀態定義

| 狀態 | 意思 | 升級條件 |
|:----:|------|----------|
| 🔴 | 推理鏈整條建不起來 | 能在引導下走完一次 → 🟠 |
| 🟠 | 走得完但需要提示 | 換案例能獨立走完 → 🟡 |
| 🟡 | 獨立走得完，但跟某概念混淆 | 能說出兩者差異並各舉一例 → 🟢 |
| 🟢 | 不同案例連續答對 2 次以上 | — |
